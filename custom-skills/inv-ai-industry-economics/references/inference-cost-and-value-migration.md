# Inference Cost and Value Migration

## Compact causal model

`Capability-adjusted cost decline`
→ `more economically viable tasks`
→ `more users/devices × more tasks per user`
→ `cloud/local routing and total compute response`
→ `bottlenecks migrate`
→ `profit pools reallocate`

The chain fails if any link fails. In particular, benchmark gains do not create economic value unless task success, reliability, adoption, and monetization follow.

## Four cost lenses

| Lens | Include | Common mistake |
|---|---|---|
| Per token | direct serving price | comparing unlike model quality |
| Per run | all context, output, tools, retries | ignoring agent amplification |
| Per successful task | review and expected error loss | treating first-pass output as completion |
| Enterprise TCO | hardware/API, power, utilization, staff, security | calling local inference “free” |

## Demand elasticity matrix

| Unit cost change | Usage change | Likely result |
|---|---|---|
| Falls rapidly | Usage grows slowly | total compute may decline |
| Falls rapidly | Usage grows faster | Jevons-style compute expansion |
| Routine work moves local | hard work escalates cloud | hybrid demand; endpoints and cloud both grow |
| Model gets cheaper but unreliable | review remains high | weak economic adoption |

## Profit-pool questions by layer

### Foundation models
- Is the model frontier-differentiated or replaceable?
- Does serving efficiency offset API price compression?
- Is there ecosystem, trust, or distribution lock-in?

### Cloud and control plane
- Can the platform monetize hosting, routing, data, identity, security, and observability even when the chosen model is open source?
- Do AI revenue and gross profit outgrow capex and depreciation?

### Semiconductors
- Which component is actually constrained: compute, memory capacity, bandwidth, packaging, networking, power, or cooling?
- Does endpoint volume offset lower compute per task?

### Data
- Are rights clear and data fresh, structured, exclusive, and connected to a feedback loop?
- Does the data improve decisions or merely exist?

### Workflow applications
- Can the product complete an action, not merely draft text?
- Does it control permissions and system integrations?
- Is value measurable through revenue, conversion, retention, or labor savings?

### Distribution
- Who owns the default entry point and user intent?
- Can that owner monetize usage rather than subsidize it indefinitely?

## Local/cloud production checklist

- Model weight memory plus runtime overhead and KV cache.
- Tokens per second at target context and concurrency.
- Energy, thermal, and battery limits.
- Update and security process.
- Data residency and audit requirements.
- Utilization: dedicated local hardware versus elastic cloud.
- Confidence-based escalation and human-review path.

## Monitoring dashboard

### Cost and quality
- Capability-adjusted price per million tokens.
- Cost per successful task.
- Production pass rate and human-review rate.
- Tool-call success and retry frequency.

### Adoption
- Paid seats and active agents.
- Tasks per user or events processed per agent.
- Endpoint shipment mix with sufficient memory/NPU capability.
- Trial-to-production conversion.

### Monetization
- AI ARPU or outcome-based revenue.
- Advertising/commerce conversion lift.
- Labor or support-cost reduction.
- Incremental gross profit after inference cost.

### Capital returns
- AI revenue/gross profit versus capex and depreciation.
- Datacenter and accelerator utilization.
- FCF conversion.
- Advanced-node and packaging utilization.

## Disconfirming signals

- Inference prices fall but paid adoption remains weak.
- Human review cost does not decline.
- Agent errors prevent access to production permissions.
- Endpoint AI produces no sustained usage or replacement cycle.
- Cloud price compression outpaces token-volume growth.
- Capex and depreciation rise faster than AI gross profit.
- Application usage rises without ARPU, conversion, retention, or cost benefits.

## Portfolio mapping template

For each holding:

1. Exposure type: direct / enabling / indirect / narrative-only.
2. Exact mechanism: revenue, cost reduction, moat, or asset utilization.
3. Required proof: measurable operating or financial metric.
4. Counter-risk: substitution, price compression, capex, execution.
5. Trigger: strengthen / weaken / hold.
6. Current weight and correlated industry exposure.

Do not translate a stronger theme into an automatic add when the portfolio already has concentrated correlated exposure.
