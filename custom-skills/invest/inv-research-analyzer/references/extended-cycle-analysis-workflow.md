# 研报驱动的周期股深度分析工作流

当研报分析需要延伸到「周期判断 + 行情 + 投资结论」时，按以下扩展流程执行。
本文件是 `inv-research-analyzer` 的扩展参考，不替代主 SKILL.md 的研报抽取流程。

## 触发条件

用户在研报解读基础上追问：
- "这轮周期什么时候见顶/结束？"
- "现在还能买吗？"
- "周期股怎么估值？"
- 涉及半导体、存储、面板、航运、大宗商品等典型周期行业

## 扩展流程（在研报抽取完成后）

### Step 1: 网络补充搜索（供需/价格/资本开支）

研报数据有时效性，需用最新信息补充判断：

```bash
# 优先用 Brave Search（英文关键词，无编码问题，结构化摘要质量好）
curl -sL --max-time 20 -A "Mozilla/5.0" \
  "https://search.brave.com/search?q=KEYWORD" 2>/dev/null \
  | sed "s/<[^>]*>/ /g" | tr -s " " \
  | grep -iE "(关键词1|关键词2)" | head -30

# 中文内容用搜狗微信（注意 GBK 编码问题，需 iconv 转码）
curl -sL --max-time 20 -A "Mozilla/5.0" \
  "https://wx.sogou.com/weixin?type=2&query=KEYWORD" 2>/dev/null \
  | iconv -f gbk -t utf-8 2>/dev/null \
  | sed "s/<[^>]*>/ /g" | tr -s " " \
  | grep -iE "(关键词1|关键词2)" | head -30
```

搜索关键词设计原则：
- 供需面：`{行业} supply demand outlook {年份}`
- 价格趋势：`{产品} contract price trend {年份}`
- 资本开支：`{客户} capex spending {年份}`
- 周期判断：`{行业} super cycle when end`

### Step 2: 行情获取（注意市场覆盖限制）

| 市场 | 工具 | 备注 |
|------|------|------|
| A 股 / ETF | `inv-stock-data` snapshot | 完整支持 |
| 美股 / 港股 | `inv-stock-data` snapshot | 需代理；Yahoo Finance |
| 韩股（.KS）/ 日股（.T） | **Brave Search** | inv-stock-data/yfinance 不支持，搜索 `{公司名} stock price` 获取 |
| 其他非标市场 | Brave Search 或直接访问财经网站 | — |

### Step 3: 周期位置判断框架

对周期股，需回答以下问题（按优先级）：

1. **当前处于周期什么位置？**
   - 价格/盈利/估值相对历史周期的分位数
   - 供给端：产能利用率、新产能投产时间表
   - 需求端：下游资本开支增速、订单可见性

2. **这轮周期是否有结构性不同？**
   - LTA（长期协议）锁定比例
   - 供给侧刚性约束（环保/技术壁垒/资本密集度）
   - 需求结构变化（AI vs 传统需求）

3. **见顶信号跟踪指标（按优先级）**
   - 产品合约价环比涨幅连续收窄（最直接）
   - 下游客户资本开支增速降至个位数
   - LTA 覆盖比例下降
   - 新产能投产进度
   - 汇率/政策变化

4. **三场景时间线**
   - 悲观：周期提前结束的触发条件与概率
   - 基准：最可能见顶时间与驱动因素
   - 乐观：周期延长的条件与概率

### Step 4: 估值特殊性

周期股估值不能简单套用 PE：
- **高 PE 可能是买入信号**（盈利谷底，PE 虚高）
- **低 PE 可能是卖出信号**（盈利峰值，PE 虚低）
- 优先使用：EV/EBITDA、PB 相对历史分位、前瞻 PE（基于周期中段盈利）
- 给出悲观/基准/乐观三场景估值

### Step 5: 投资结论格式

```markdown
## 周期股综合分析

### 周期位置
- 当前阶段：{加速期/平台期/见顶回落期}
- 核心驱动：{1-2 句话}

### 结构性支撑因素（若有）
1. …

### 见顶信号跟踪指标（按优先级）

### 三场景时间线
| 场景 | 概率 | 见顶时间 | 触发条件 |
|------|------|----------|----------|

| 乐观 | Z% | … | … |
```

## 已知陷阱

1. **"周期还没结束" ≠ "股票还没见顶"**：股价往往领先基本面 6-12 个月见顶
2. **韩国/日本股票行情获取**：inv-stock-data 不支持，必须用 Brave Search 替代
3. **搜狗微信 GBK 乱码**：curl 直接 sed 会乱码，必须 iconv 转码或用 Python requests
4. **研报 PE 与实际 PE 差异**：外资研报用 IFRS/K-GAAP，与 Yahoo Finance 口径不同，需标注
5. **汇率换算**：韩股价格需换算为 USD 或 CNY 时，必须用实时汇率，不得用记忆中的旧汇率

## 转公众号文章规则

当用户要求将投资分析转为公众号文章时，遵循以下规则：

### 结构原则

1. **逻辑链只进不退**：规律 → 验证 → 解释 → 实操 → 结论。不得先给结论再讲规律，不得回头重复已呈现的数据
2. **消灭重复数据**：同一组数据只出现一次。如果两节需要同一数据，合并为一节，或在一节中完整呈现、另一节仅引用结论
3. **每节"先结论后论证"**：读者扫标题和加粗就能抓住主线，不需要读完每一段
4. **支撑逻辑不独立展开**：如果支撑因素（如"三个硬逻辑""四个终结信号"）是服务于某个核心论点的，压缩为该论点的论据，不单独成节。独立成节会导致主线偏移到"牛市会不会结束"而非"股价怎么判断顶部"

### 数据呈现

5. **区分数据性质**：表格中必须标注每行数据的来源性质——"已发布"/"券商一致预期"/"推算"。推算数据必须加脚注说明不确定性
6. **推算数据不得与确认数据混排无标注**：用户会质疑未标注的预估数据，影响全文可信度

### 周期股文章的核心框架

7. **"加速度"框架**：周期股股价见顶 = 合约价环比涨幅从加速转为减速的那一刻，不是涨幅归零时。用跑步类比（速度 vs 加速度）解释
8. **犹豫期必须解释**：加速度拐点已现但股价不立刻见顶，需解释三个原因（绝对涨幅仍大、前瞻PE陷阱、结构性支撑），并给出基准判断
9. **PE陷阱必须点明**：周期股前瞻PE最低时恰恰最危险——PE低是因为EPS预测基于周期峰值，涨幅收窄后EPS下修会让PE"被动变贵"
