# 价值成长（QARP）选股与操作技能

## 核心定位

本技能是用户主打法"价值成长（QARP）"的执行层，解决的核心问题：

> 好公司不等于好股票，好价格才是买入理由。

**架构**：本技能依赖 `inv-valuation-engine` 提供估值引擎（脚本 + 定量评分框架），自身聚焦 QARP 特有的操作决策层：选股闸门 → 估值纪律 → 买入/持有/卖出 → 组合约束。

### 三个命令的使用场景

| 命令 | 场景 | 执行范围 |
|------|------|----------|
| `/qarp` | 新标的完整分析 | 估值快照 → 五档结论 → 三道闸门 → 估值纪律 → 买入必答 → 组合检查 → 结论 |
| `/qarp_screen` | 快速筛选是否值得深入研究 | 只跑选股闸门（三道），不跑完整估值。通过则输出"值得深入研究，建议 /qarp"，不通过则输出原因 |
| `/qarp_check` | 对已有持仓做持有/加仓/减仓检查 | 跳过闸门，直走估值快照 → 逻辑检查 → 估值检查 → 组合检查 → 持有/加仓/减仓/卖出结论 |

## 快速命令

估值脚本统一走 `inv-valuation-engine`，路径中 `{valuationDir}` = `{baseDir}/../inv-valuation-engine`，`{researchDir}` = `{baseDir}/../inv-research-analyzer`。

```bash
# 代理设置（美股/港股需要）
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890

# 1) 抓取估值快照（文本）
uv run {valuationDir}/scripts/valuation_snapshot.py AAPL

# 2) 抓取估值快照（JSON）
uv run {valuationDir}/scripts/valuation_snapshot.py 600519 --output json
uv run {valuationDir}/scripts/valuation_snapshot.py 0700.HK --output json

# 3) 直接输出五档估值报告
uv run {valuationDir}/scripts/valuation_report.py 600660

# 4) 指定公司类型
uv run {valuationDir}/scripts/valuation_report.py 002475 --company-type tech

# 5) 同行相对估值比较
uv run {valuationDir}/scripts/valuation_compare.py 002475 601138 002241 --company-type tech

# 6) Markdown 表格版
uv run {valuationDir}/scripts/valuation_report.py AAPL --output markdown

# 7) 手动估值计算（脚本失败时降级）
uv run {valuationDir}/scripts/valuation_manual_compute.py \
  --price 98.78 --shares 14.82 --fx 7.15 \
  --ni-gaap 978.43 --ni-nongaap 1073 --eps-fy1 82.08 \
  --equity 4133.85 --equity-prev 3133.13 \
  --revenue 4318.46 --gross-profit 2430.44 --op-income 931.02 \
  --fcf 1057.94 --cash 1089 --investments 3134 --debt 54 \
  --scenario-profit "悲观,1127,8|基准,1300,10|乐观,1500,12"
```

## 一、估值框架（五档结论）

估值定量框架（公司类型识别、定量阈值、结论生成规则）以 `inv-valuation-engine` 的 `references/scoring-rules.md` 为权威标准，本技能只补充 QARP 特有的约束。

### 1.1 QARP 安全边际要求

| 标的类型 | 最低安全边际 | 买入最大估值上限 | 说明 |
|----------|-------------|-----------------|------|
| 龙头白马/宽护城河 | ≥20% | 内在价值的80% | 质量溢价可接受较小安全边际 |
| 成长股/中型公司 | ≥30% | 内在价值的70% | 增长不确定性需要更大保护 |
| 高波动科技股 | ≥40% | 内在价值的60% | 波动本身是风险来源 |
| 周期股/困境反转 | ≥50% | 内在价值的50% | 高不确定性需要极端安全边际 |

### 1.2 PEG 使用规则

- 仅用于盈利稳定、增速可估的标的（增速 10-30% 最适用）
- 增速取一致预期下限或自建保守假设，不用 Yahoo `earningsGrowth`
- 周期股、低增速成熟公司（<10%）、持续亏损公司不使用 PEG
- QARP 合理 PEG 区间：0.8-1.2

## 二、选股三道闸门

### 2.1 第一道：行业与商业模式

不通过则直接跳过，不看财务数据。

| 维度 | 要求 | 判断方法 |
|------|------|----------|
| 行业空间 | TAM 足够大，或渗透率仍在提升 | 查行业报告/研报，看行业增速 CAGR |
| 竞争结构 | 集中度提升中，或龙头护城河清晰 | CR3/CR5 趋势 + Porter 五力速判 |
| 商业模式 | 能说清"谁付钱、为什么付、凭什么持续付" | 用三句话测试，说不清则不通过 |
| 周期属性 | 明确标的属于成长/消费/周期/金融哪类 | 决定后续估值口径和持有逻辑 |

**研报输入（第一道闸门）**：
- 从研报提取行业增速、TAM 估算、渗透率数据，作为"行业空间"判断的事实依据
- 从研报提取竞争格局描述（CR3/CR5、份额变化、新进入者威胁），与 Porter 五力结果交叉验证
- 从研报提取商业模式评价（护城河来源、定价权、客户粘性），辅助"三句话测试"
- 若多家研报对行业前景判断一致（一致看多/看空），标注为强信号；若分歧显著，标注不确定性
- 周期属性判断参考研报中的周期定位分析（详见 `inv-research-analyzer` 的 `references/extended-cycle-analysis-workflow.md`）

**商业模式速判清单**：
- 赚钱不辛苦：毛利率≥30%，净利率≥15%，低资本开支 → 优先
- 赚钱辛苦但能赚：毛利率 15-30%，需持续投入 → 可以，但要求更大安全边际
- 辛苦且不一定赚：低毛利、高波动、重资产 → 不符合 QARP，跳过

### 2.2 第二道：财务质量

| 指标 | 门槛 | 权重 | 说明 |
|------|------|------|------|
| ROE | >15%（近3年均值） | 高 | 资本回报率是质量核心 |
| 自由现金流 | 正值，FCF/净利润 >60% | 高 | 利润质量检验 |
| 毛利率 | 行业前 1/3 或稳定提升 | 中 | 竞争优势的财务体现 |
| 资本配置 | 分红+回购合理，并购不乱来 | 中 | 管理层对股东友好的硬证据 |
| 资产负债表 | 净负债率合理，无隐性风险 | 中 | 排雷 |

**允许 1-2 项不达标，但必须说清原因和改善路径。3 项以上不达标则不通过。**

**研报输入（第二道闸门）**：
- 从研报提取卖方对未来 2-3 年 ROE、毛利率、FCF 的预测趋势，与 yfinance 历史数据对照：若多家研报一致预期 ROE 下行或 FCF 恶化，即使历史数据达标也应标注风险
- 从研报提取盈利质量讨论（Non-GAAP 调整项、一次性收益/损失、CapEx 结构），补充 yfinance 无法覆盖的定性判断
- 从研报提取资产负债表风险提示（表外负债、商誉减值风险、应收账款质量），作为第二道闸门"排雷"的补充
- 若研报对财务趋势的判断与 yfinance 数据矛盾，优先以财报事实为准，但标注分歧供后续跟踪

### 2.3 第三道：管理层评估（加分项）

- 资本配置纪律：历史增发/回购/分红记录
- 激励一致性：管理层持股比例、期权行权条件
- 对股东回报的态度：实际行动 > 口号

**管理层不达标不直接否决，但影响仓位上限（最多卫星仓位 2-5%）。**

**研报输入（第三道闸门）**：
- 从研报提取管理层评价（资本配置记录、并购纪律、关联交易、股权激励合理性），卖方研报常含管理层访谈纪要，是 yfinance 无法覆盖的定性信息
- 从研报提取股东回报政策（分红率趋势、回购执行力度、历史上是否摊薄股东权益），辅助判断"实际行动 vs 口号"
- 若多家研报对管理层评价一致（正面或负面），标注为较强信号；若研报未涉及管理层讨论，标注信息缺口

## 三、估值纪律（QARP 核心）

### 3.1 估值-质量矩阵

| 场景 | 估值要求 | 仓位 | 操作 |
|------|---------|------|------|
| 好公司 + 估值合理 | PE 低于行业中位数或自身5年中位数 | 核心仓位 5-15% | 可以买入 |
| 好公司 + 估值贵 | PE 高于5年 75% 分位 | 不买 | 加入观察，等回调 |
| 一般公司 + 估值便宜 | PE/PB 处于历史低位 | 卫星仓位 2-5% | 小仓位博价值回归 |
| 一般公司 + 估值贵 | — | 不碰 | — |

### 3.2 QARP 估值合理区间判断

| 五档结论 | QARP 操作含义 |
|----------|--------------|
| 低估 | 积极买入，可给核心仓位 |
| 合理偏低 | 可以买入，正常仓位 |
| 合理 | 持有为主，新买入需谨慎、小仓位 |
| 合理偏高 | 不买入，持有者可考虑减仓 |
| 高估 | 不碰，持有者分批减仓 |

**关键规则**：好公司但估值贵时，建议加入观察等回调，而非追高建仓。

### 3.3 卖方共识交叉校验

卖方研报的盈利预测和评级需纳入估值判断，但**不能直接替代独立估值**：

| 用法 | 说明 |
|------|------|
| **增速假设参照** | 取多家研报的营收/EPS 增速预测区间，与自建假设对比。若自建假设远高于卖方共识（>5pp），需重新审视假设合理性 |
| **一致预期偏差警示** | 若当前 PE 远低于卖方一致预期隐含的合理 PE（即卖方普遍看多但市场不买账），说明市场在定价卖方未覆盖的风险，需深入调查 |
| **卖方乐观偏差修正** | 卖方目标价平均存在 10-15% 乐观偏差（尤其是承销关系券商）。使用卖方目标价时，按 0.85-0.9 系数打折后作为参考上限 |
| **分歧度信号** | 若各家目标价/盈利预测分歧极大（最高/最低 > 1.5x），说明标的未来高度不确定，应要求更大的安全边际（+10pp） |

**使用原则**（来自 `inv-research-analyzer` 的 `references/research-integration-notes.md`）：
- 卖方目标价**不**作为独立估值依据
- 卖方一致预期可作为增速假设参考，但必须人工校验合理性
- 卖方暗含风险应纳入本技能的风险框架
- 冲突时以财报事实为准

## 四、买入执行

### 4.1 买入前必答清单

1. 行业和商业模式看得懂吗？
2. 核心竞争优势是什么？能持续多久？
3. 当前估值在历史什么位置？有安全边际吗？
4. 买入理由是什么？（一句话）
5. 打脸条件是什么？（什么情况下认错卖出）
6. 目标仓位多少？分几次建仓？

**6 问全部有明确答案才可买入。任何一问答不上来，先研究再决定。**

**打脸条件制定指南**（第 5 问）：
- 优先从研报"核心风险"和"隐含假设与失效条件"中提取关键风险，转化为可观测的触发条件
- 区分两类打脸条件：**逻辑破坏型**（竞争优势丧失、行业格局恶化、管理层失信）和**数据恶化型**（ROE 连续 2 季 < 阈值、FCF/NI < 50%、毛利率趋势性下滑）
- 卖方研报覆盖的风险往往偏向已知风险（政策、汇率、竞争），需额外补充卖方**未覆盖**的尾部风险（技术颠覆、地缘政治、管理层变动）
- 打脸条件必须是**可观测、可验证、有时间维度**的（如"核心客户流失率连续 2 季 >5%"），而非模糊表述

### 4.2 分批建仓规则

- 任何新买入默认分 **2-3 次**建仓，间隔至少 **1 周**
- 首次建仓不超过目标仓位的 **50%**
- 加仓条件：首次买入后下跌 5-10% 且逻辑未变，加第二次
- 单只股票仓位上限 **25%**

### 4.3 买入时估值记录

买入时必须记录：
- 买入时 PE/PB 及历史分位
- 买入时股价
- 买入理由（一句话）
- 打脸条件
- 目标仓位与实际仓位

## 五、持有与跟踪

### 5.1 持有原则

- 持有周期：1-3 年，等逻辑兑现
- 不因短期波动操作，除非波动反映了逻辑变化
- 分红是持有的安全垫，不是买入理由

### 5.2 跟踪方式（轻跟踪）

| 频率 | 检查内容 | 触发操作 |
|------|---------|---------|
| 季度 | 财报核心指标（收入增速、毛利率、FCF、ROE） | 指标恶化 → 深入分析 |
| 事件驱动 | 重大公告/行业变化 | 复盘逻辑是否变化 |
| 估值检查 | PE/PB 分位变化 | 估值透支 → 考虑减仓 |

### 5.3 跟踪必查项

- 买入理由是否还成立？
- 打脸条件是否触发？
- 估值是否已透支未来 1-2 年增长？

## 六、卖出条件

### 6.1 三种卖出场景

| 类型 | 触发条件 | 操作 |
|------|---------|------|
| 逻辑破坏 | 打脸条件触发，内在价值判断改变 | 果断卖出，不分批 |
| 估值透支 | PE 远超历史高位，透支 2 年以上增长 | 分 2-3 次减仓 |
| 机会成本 | 发现明显更好的标的，且仓位已满 | 卖出较弱的，换入更强的 |

### 6.2 不卖的情况

- 价格下跌但逻辑没变 → 考虑加仓，不卖
- 短期利空但不影响长期竞争力 → 持有
- 市场恐慌但公司基本面稳健 → 持有甚至加仓

### 6.3 卖出执行规则

- 逻辑破坏型：可以一次性卖出
- 估值透支/机会成本型：分 2-3 次减仓，间隔至少 1 周
- 卖出后记录原因，供复盘用

## 七、组合约束

| 约束项 | 限制 | 说明 |
|--------|------|------|
| 单只股票仓位 | ≤25% | 硬约束 |
| 现金最低 | ≥2%，理想 5-10% | 保持弹药 |
| 单一行业集中度 | ≤40% | 防行业系统性风险 |
| 调仓执行 | 分 2-3 次，间隔 ≥1 周 | 防冲动操作 |

### 组合结构

| 层级 | 占比 | 标的数量 | 特征 |
|------|------|---------|------|
| 核心仓位 | 60-70% | 5-8 只 | 高质量公司，估值合理时买入 |
| 卫星仓位 | 20-30% | 3-5 只 | 周期股、困境反转、事件驱动 |
| 现金 | 5-10% | — | 等恐慌时加仓用 |

### 现金管理

- 现金 >15%：主动寻找机会建仓
- 现金 5-10%：正常区间，按计划操作
- 现金 <5%：停止新建仓，只做换仓

## 八、市场环境适配

| 环境 | 核心仓位 | 卫星仓位 | 现金 |
|------|---------|---------|------|
| 牛市主升 | 持有，不追高 | 可适当增加成长/周期 | 5% 下限 |
| 震荡市 | 正常持有 | 事件驱动为主 | 5-10% |
| 熊市/恐慌 | 加仓核心持仓 | 困境反转机会 | 可临时升至 15%+ |
| 利率下行 | 利好质量成长，可适度加仓 | — | — |
| 利率上行 | 偏向价值/短久期，减少高估值成长 | 偏高 | — |

## 九、执行流程

### 9.1 对新标的的完整 QARP 分析

#### 阶段一：数据采集（并行）

以下两项互不依赖，**应尽可能并行执行**。有子代理能力的 Agent 应同时派发两个子任务；无子代理能力的 Agent 按顺序执行即可。

**注意**：这两项是真正的独立数据源（不同脚本/文件），并行不会重复劳动。后续阶段二、三依赖共享数据，不应派给子代理。

| 并行任务 | 脚本 | 预计耗时 |
|---------|------|---------|
| **A. 估值快照** | `uv run {valuationDir}/scripts/valuation_snapshot.py <代码> --output json` | 10-30s |
| **B. 研报提取** | 1) 读 `~/股票研报/Index.md` 匹配子文件夹 → 2) `python3 {researchDir}/scripts/research_pdf.py extract --folder <子文件夹>` → 3) 按结构化模板整理（共识/分歧/盈利预测/风险/隐含假设/交叉验证点） | 10-30s |

- A 是必须的；B 若无本地研报则走 Web 降级（`inv-research-analyzer` 的 `references/web-fallback-for-non-a-share.md`）
- 估值定量判断以 `inv-valuation-engine` 的 `references/scoring-rules.md` 为准
- 研报提取后**必须**按结构化模板整理（见 `inv-research-analyzer` 输出模板），而非仅输出原始文本。重点关注：共识观点（流入第一/二道闸门）、分歧观点（流入估值纪律的分歧度信号）、盈利预测区间（流入估值纪律的增速假设校验）、核心风险+隐含假设（流入买入前必答第 5 问的打脸条件制定）

#### 阶段二：增量信息检查（依赖阶段一全部结果）

逐级检查，不得跳过：

- yfinance 覆盖了什么？缺什么？
- 研报覆盖了什么？时效性够吗？
- **若仍有关键缺口**（如反垄断进展、CapEx指引、行业政策变化、竞争格局最新变化），必须用 Agent WebFetch 补充后再出结论

#### 阶段三：分析与决策（依赖阶段二）

按顺序执行：

1. **输出五档结论**：按 `inv-valuation-engine` 的估值框架，结合其 `references/scoring-rules.md` 定量阈值，给出五档估值判断
2. **选股闸门**：按三道闸门逐项检查，任一闸门不通过则输出"不通过"结论
3. **估值纪律**：根据本技能的估值-质量矩阵（第三章）判断是否值得买入
4. **买入前必答**：6 问全部有答案才可建议买入
5. **组合检查**：检查仓位、集中度、现金比例是否允许新建仓
6. **输出结论**：买入/观察/不碰，附价格区间、分批建仓计划、打脸条件
7. **机会成本对比**：若近期分析过同行业或同市场标的，输出简要对比表（估值、质量、风险、仓位建议），帮助用户做机会成本判断

### 9.2 对已有持仓的 QARP 检查

1. **运行估值快照**：获取最新估值数据
2. **逻辑检查**：买入理由是否还成立？打脸条件是否触发？
3. **估值检查**：当前估值是否透支未来增长？
4. **组合检查**：仓位是否超标？集中度是否过高？
5. **输出结论**：持有/加仓/减仓/卖出，附理由和执行计划

### 9.3 完整分析流程

```
阶段一：数据采集（并行）
┌──────────────────┐ ┌──────────────────┐
│ A. 估值快照       │ │ B. 研报提取       │
```

## 十一、常见陷阱与防范

| 陷阱 | 防范 |
|------|------|
| 好公司买贵了，等估值消化 2-3 年 | PE 高于5年中位数不建核心仓 |
| 逻辑变了不肯认错 | 买入时写清打脸条件，触发就执行 |
| 追热点买自己不懂的行业 | 第一道闸门不通过就不看 |
| 仓位太集中 / 现金太少 | 单只≤25%，行业≤40%，现金 5-10% |
| 频繁交易 | 1-3 年周期，轻跟踪，大变化再调 |
| PEG 陷阱：短期高增速不可持续 | 增速取一致预期下限，不用单季 GAAP `earningsGrowth` |
| Forward PE 口径失真 | 互联网/科技公司（腾讯/阿里/美团等）的 Yahoo Forward PE 常基于 Non-GAAP 调整后 EPS，隐含增速虚高（>30%）。一律做常识校验 `隐含增速 = (1/forwardPE)/(1/trailingPE)-1`，>20% 则手算修正并以 Non-GAAP Trailing PE 为主锚点。A+H 双上市额外注意 GAAP vs Non-GAAP 差异 |
| 互联网公司 GAAP 净利润失真 | 参见 `inv-valuation-engine` 的 `references/internet-platform-valuation.md`，用 Normalized 净利润。**注意**：Normalized Income 同比增速也可能失真——当对比基期含一次性投资收益/减值时，应优先用**经营利润（Operating Income）增速**作为核心增长指标 |
| AI CapEx 暴增期 FCF 失真 | 互联网平台在 AI 基础设施投资周期中，CapEx 可从营收 20%+ 跳升至 35%+，导致 FCF/NI 从 >80% 降至 <80%。此时 FCF 下降不代表利润质量恶化，而是投资型支出。判断方法：区分维持型 CapEx（~营收15-20%）与投资型 CapEx（增量部分），用「经营现金流 - 维持型 CapEx」估算可持续 FCF |
| 5年价格分位受极端值扭曲 | 5年区间若包含极端暴跌（如 2022 年 META 从 $384→$89、中概股集体暴跌），分位会被严重拉低。应同时报告 3 年分位和 52 周位置作为校验；52 周位置 <40% 通常比 5 年分位 >70% 更能反映近期估值水平 |
| 脚本增速假设需校验 | 运行 valuation_report.py 后检查增速是否来自 `earningsGrowth`，若是则人工替换 |
| valuation_report.py 数据不足时输出极简 | 当底层脚本因数据源失败返回极少字段时，valuation_report.py 可能仅输出极简结论。应视为脚本失败，降级为手动按估值框架计算，不得将极简报告结论作为 QARP 五档判断依据。标注"脚本数据不足，已手动计算" |
| 搜索功能用于金融查询效率低 | 搜索引擎对金融查询低效+CAPTCHA。增量信息优先走 yfinance + 本地研报，最后才考虑网页抓取 |
| 卖方目标价当独立估值依据 | 卖方存在结构性乐观偏差（承销关系、佣金依赖）。卖方目标价打 0.85-0.9 折后仅作参考上限，不替代独立估值。一致性高不等于正确——2008 年 crisis 前卖方对金融股评级也高度一致 |
| 卖方共识 = 市场共识 | 卖方共识 ≠ 市场定价。若当前 PE 远低于卖方一致预期隐含 PE，说明市场在定价卖方未覆盖的风险——这正是需要深入调查的盲点 |
| 研报同质化误判 | 多数卖方研报共享 Bloomberg 一致预期数据源，看似"多家一致"实则同源。真正的独立判断来自不同研究框架（如买方视角 vs 卖方视角、定量模型 vs 定性调研）的交叉验证 |
| 忽视研报"暗含风险" | 研报末尾的风险提示（下行风险、敏感性假设）通常比封面的"买入"评级更有价值。卖方不在封面写的风险（地缘政治、技术颠覆、管理层变动）往往是真正的关键风险 |
| 忽视卖方盲点 | 卖方系统性忽视某些风险类型（如台海地缘对台积电、AI 投入从被奖励到被惩罚的转折）。需在分析中主动补充卖方未覆盖的尾部风险 |

## 十三、研报与决策框架的交叉验证

研报不是一次性的"提取→贴入模板"，而是贯穿 QARP 全流程的交叉验证工具。

### 13.1 研报输出到决策环节的映射

| 研报结构化产出 | 流入 QARP 环节 | 用法 |
|---------------|---------------|------|
| 共识观点（行业/TAM/竞争） | 第一道闸门 | 行业空间判断的事实依据 |
| 共识观点（财务趋势） | 第二道闸门 | ROE/FCF/毛利率趋势的卖方判断 |
| 管理层评价 | 第三道闸门 | 资本配置纪律、股东回报态度 |
| 盈利预测区间 | 估值纪律 3.3 | 增速假设校验、一致预期对照 |
| 分歧观点 | 估值纪律 3.3 | 分歧度 → 安全边际调整 |
| 核心风险 | 买入必答 第 5 问 | 打脸条件制定的输入 |
| 隐含假设与失效条件 | 买入必答 第 5 问 | 逻辑破坏型卖出条件 |
| 卖方盲点 | 买入必答 第 6 问 | 仓位上限调整（高不确定性 → 降低仓位） |
| 交叉验证点 | 五力/估值 | 供下游技能引用的具体验证点 |

### 13.2 交叉信号强度判断

同一数据点在多个独立来源被印证时，信号强度递增：

| 信号层级 | 描述 | 对决策的影响 |
|----------|------|-------------|
| **强信号** | yfinance + 多份研报（不同券商）均指向同一结论 | 可作为核心判断依据 |
| **中等信号** | yfinance + 1 份研报方向一致，或仅研报之间有共识 | 作为参考，需额外验证 |
| **弱信号** | 仅 1 份研报提及，yfinance 无法直接验证（如管理层定性评价、行业调研纪要） | 标注不确定性，不作为核心依据 |
| **分歧信号** | 不同券商对同一问题判断相反 | 标注分歧，调查分歧根源，要求更大安全边际 |
| **卖方盲点信号** | 所有研报均未提及某关键风险（如地缘政治、技术颠覆） | 必须独立补充，不能因"卖方没提"而忽略 |

### 13.3 研报与独立判断的优先级

遵循以下优先级解决冲突：
1. **财报事实 > 卖方预测**：若卖方预测与已披露财报趋势不符，以财报为准
2. **多源交叉验证 > 单一来源**：多个独立来源（yfinance + 研报）一致时，可信度最高
3. **卖方分歧本身是信号**：不要急于"解决"分歧——高度分歧意味着不确定性高，应要求更大安全边际
4. **卖方盲点 = 独立研究机会**：卖方系统性忽视的风险维度，正是深度研究的超额收益来源

### 13.4 无本地研报时的降级路径

当 `~/股票研报/Index.md` 无匹配时，按以下优先级降级：
1. **Web 降级**：按 `inv-research-analyzer` 的 `references/web-fallback-for-non-a-share.md` 执行（Yahoo Finance 分析师数据、搜狗微信搜索、Brave Search）
2. **标注信息缺口**：在输出模板的"卖方研报摘要"中明确标注"无本地研报，已走 Web 降级 / 无可用研报"，并说明对分析完整性的影响
