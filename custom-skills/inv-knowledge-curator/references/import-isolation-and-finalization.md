# 批量导入的隔离与最终验收

## 工作区已有修改

- 归档脚本可能内部提交并推送整个工作区；开始前确认副作用及无关修改，不能把用户已有编辑混入导入提交。
- 优先使用独立工作树/隔离副本；若采用stash保护，记录确切stash对象及逐文件内容指纹，并保留备份。存在其他写入者时，不能假设stash捕获的清单等于此前status清单。
- 恢复后逐文件验证。出现差异时先区分自动修复、并发编辑与冲突；不得直接用旧备份覆盖现有内容。未查清前保留stash及备份，明确报告未闭环，不声称“原样恢复”。

## 并行生成与完成屏障

1. 原始PDF串行归档，记录来源、目标、哈希和正式报告身份。
2. 子任务只生成互不重叠的新条目；禁止并发操作共享索引或Git。
3. 文件存在不代表子任务完成。只有全部写入者已结束，才能进行最终lint、索引图谱重建及push；不得在子任务仍可能修改文件时提前宣告完成。
4. 子任务超时也不代表成果全失：检查实际落盘的原始输出，主流程验证并补完缺口。中间文件不能替代子任务完成证明。
5. 最后核对PDF哈希、正文格式与长度、资源配对、真实关联、索引收录、lint结果，以及本地提交与远端分支一致。
6. 异步结果晚到时，先判断是否发生最终验收后的写入；若有，应重新验收并按授权推送，不直接声称“已包含”。

## 去重与废纸篓边界

相同哈希可确认字节重复；不同哈希须核对首页正式标题、日期、机构、版本和正文。英文完整版与中文节译版不是完全重复件：保留两份资源、共用知识条目并注明版本关系。用户要求重复文件移废纸篓，不等于授权永久删除或删除库内相似主题条目。归档移走的新报告和移入废纸篓的重复件须分别统计。
