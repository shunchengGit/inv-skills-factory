# 知识库实质审计与共享写入边界

## 适用范围
批量研报导入验收、旧条目深度优化与知识库健康检查。结构扫描可以全库执行，原文抽检须明确覆盖范围；不能将重点抽检描述为全库事实背书。

## 1. 建立只读基线
- 记录HEAD、工作区状态及拟修改文件内容摘要；明确是否获准写库。
- 解析完整YAML，包括多行description及列表resource；排除index/by-tag导航，使用实际路径而非界面省略名。
- 运行只读lint及重复检查，另查无数字描述、占位摘要、自引用、目录伪引用和短正文；这些是候选，不是自动删除条件。
- 独立计算PDF哈希身份；保留原件，去重区分相同字节、同源不同用途、不同版本、不同报告期。

## 2. 原文核验优先级
每项证据至少记录：entry实际路径、PDF实际路径、正式机构/日期、物理页码、原文数字、单位、主体、时间区间、actual/guidance/analyst estimate及修改理由。

P0优先检查：
- 公司名称和代码：平台显示公司、资源目录、文件名都不能替代PDF首页主体。
- 文件性质：邀请函不是会议纪要；业绩前瞻不是实际财报；新车点评不是全行业预测。
- 金额与期间：全年指引不是季度收入；美元首位缺失必须回查原文，不凭常识补齐。
- 利润口径：GAAP、调整后、扣非、FCF、FCFF各自定义；含一次性税惠的EPS不能自动称作核心盈利。
- 预期归属：实际值对比市场共识与对比单家券商预测分开；未达到投资者高预期不一定是营收miss。
- 预测归属：单家银行预测不能改写成管理层指引或多家共识；不同机构评级与目标价分列。
- 比较口径：报告同比与固定汇率同比、A/H股与人民币/港元、季度与财年、排名与份额不得混用。

先读首页识别，再读取支持关键结论的表格/正文页。已读页找不到旧说法时标“待核”，扩大读取范围后再判定；若暂无法核验，应在候选修订中保留来源缺口说明，不将未核内容当成确定错误抹除。原文自身有冲突时保留差异，不自造统一值。

## 3. 图谱与去重的语义验收
- 有效关联只计存在、去重且非自身的entry；资源链接及裸标签不计。
- 看入链和连通分量发现仅相互引用的小圈，但不为凑全图连通强行连接无关公司。
- 关联原因指明客户需求、供应链、同公司时间线、牛熊分歧或官方数据验证。不能只写“同机构/共同关键词”。
- 同PDF的官方锚点和估值复盘、单机构解读和多源综合可以并存；不同月份周报不能按标题相似删除。
- 真正同源同用途副本合并时转移可核独有信息与入链，统一索引；不能仅以resource相同删条目。
- 仅合并确定同义标签。不合并不同季度、前瞻/复盘、半导体/功率半导体；低频标签可能代表新标的。

## 4. 单写入者与复核
候选修订保存在库外，并发子任务默认只读原库。主会话写回前比较HEAD与目标内容摘要；变化时重新读取并协调，不能用旧快照覆盖。没有证据时只报告“检测到并发变化”，不猜谁造成或为何发生。

用户中途撤销写入授权后，向全部工作流传达只读边界；能取消则取消本任务写入者，不能停止则如实说明并暂不宣称无后续写入。不要停止不属于本任务的进程或还原他人提交。

最终逐文件读回、验证diff、再统一重建与推送；远端分支名先发现，不假设main。若只读交付，则不执行会写库的验收步骤。报告明确原文核查范围、剩余缺口、尝试与实际保留的修改，不把子任务自报当成功证明。
