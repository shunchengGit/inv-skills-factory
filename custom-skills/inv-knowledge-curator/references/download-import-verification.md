# 下载目录研报入库：身份判定与验收

## 任务范围
用户要求“下载中的研报入库，重复的移到废纸篓”时，先列明研究文件；账单、发票、简历及其他私人文档不纳入。删除授权仅覆盖已确认重复件，不等于授权清理整个下载目录或库内旧条目。

## 身份与版本
- 归档前记录来源绝对路径、SHA-256、PDF首页正式标题、机构、发布日期与页数。
- 同时检查库内资源哈希和内容身份；仅搜文件名或知识条目标题不足以排除历史重复。
- 文件名日期可能是平台日期，条目日期以PDF首页发布日期为准。
- 英文完整版与中文节译版，即使主题和作者相同，也不是字节重复；读取翻译声明和章节覆盖后，可将两份PDF归档并由同一条知识记录引用，保留版本差异，不能计为两个独立观点来源。
- 不同哈希、相近标题不能直接送入废纸篓。需核对版本、正文和附件，确认不存在独有内容；不确定则保留。

## 归档与验收
- `km_import.py res` 会移动源文件并触发提交/推送；后续读归档路径，不再读旧下载路径。
- 归档前后逐份比对SHA-256，确认保存的PDF与输入一致。并行生成条目时，资源归档仍串行，子任务不运行共享索引或Git操作。
- 每条记录需有原文页码、明确预测/历史快照/厂商宣称的口径、至少两条真实关联。多语言版本引用均需保留且被PDF配对检查识别。
- 等全部子任务完成，再统一lint --fix；验证条目落盘、标题可在索引检索、图谱重建、PDF配对和Git推送，而不是只接受子任务自报成功。
- 最终摘要分别报告：输入PDF数、独立知识记录数、版本合并情况、实际移入废纸篓数，以及尚未闭环事项。无完全重复件时明确报告0，不为满足清理措辞而删除独有版本。

## 原有修改的边界
入库脚本会提交工作区，必须在首次写操作前识别已有修改并明确隔离范围。原有修改的恢复验证与新资料入库验证是两个独立验收项；恢复出现差异不能宣称“原样恢复”。保留保护副本并报告差异，不能为了通过检查而覆盖未知的新修改，也不能把未完成的恢复尝试记为可靠恢复流程。
