# 加仓决策框架（持仓加码）

与 `position-reduction-framework`（减仓）成对使用。本技能只解决一个问题：

> 好公司 + 逻辑未坏 ≠ 现在该加。加仓要的是价格空间与触发条件，不是复述质量。

估值口径、五档结论、闸门规则一律走用户自有的 `inv-qarp-strategy` / `inv-valuation-engine` / `inv-stock-data`；先 `skill_view` 加载它们再动手，本技能只补加仓特有的决策层与陷阱。

## 输出形状（用户偏好，每次都照做）

1. **第一行给结论**：加仓 / 不加仓 + 具体股数或金额；通常补充当前仓位。用户明确要求“仅考虑价值”时，先独立回答绝对估值与预期回报，不用仓位、现金或交易频率否决价值判断；持仓仅用于资金测算，组合层结论另列。不要铺垫、不要先讲公司质量。
2. 数据锚小表：现价与时点、TTM PE、Forward PE（当年E/次年E）、价格分位（5年与52周分开写）、股息率。
3. 质量端一段（为什么逻辑没坏）→ 不加的理由分条（为什么现在不动手）→ **触发条件写死**（if X then buy N shares）→ 打脸条件。
4. 触发条件必须可机械核对：具体价格区间、具体财务阈值、具体事件（复产/财报），并写明资金来源与分批节奏。
5. 结尾一句问是否挂提醒。不要总结已说过的内容。

## 执行步骤

1. **先读持仓主信源** `~/.hermes/memories/PORTFOLIO.md`（绝对路径，禁止模糊搜索）。拿到股数、仓位、现金比例、行业集中度。任何加仓结论都必须落在组合上下文里。
2. **拉数据**：`cs_stock_info.py all <code> --output json > /tmp/x.json` + `daily --period 5y`；A股先 `unset HTTPS_PROXY HTTP_PROXY`。禁止管道进 python。
3. **跑估值** `valuation_report.py <code> --output json`，读 `valuation_status`。`partial` 时结论可保留但必须降置信度，且不得直接转成买入动作 —— 必须人工手算 TTM PE / Forward PE 补位。
4. **手算 TTM 净利**：`FY(n-1) − H1(n-1) + H1(n)`，再用最新股数×现价得市值算 TTM PE，与行情接口的 PE 交叉验证（差异 >5% 就停下来查口径）。
5. **回溯原文**：涉及建仓或调仓至少读 2 份独立机构研报原文。先用 `--pages edges` 初筛，再对最终采用的两份运行 `km_import.py read --file <绝对路径> --pages all --max-pages 60 --max-chars 150000`，定向核验正文中的 EPS/净利预测、估值方法、目标价假设和风险段；这些内容常在中间页，仅读首尾页会漏掉。`--file` 使用 `$HOME/.inv-knowledge/res/...` 绝对路径。若 `entries` 检索为零，继续查 `res/index.md` 和 `res/{标的}/` 文件名，三处均无命中后才能判定知识库无覆盖。
6. **算安全边际与回报**（见下）→ **核算购买力，单列组合约束** → 出结论与触发条件。平台公司高投入期先按 `references/platform-owner-earnings.md` 统一现金流、股权激励和预测口径，不以自动评分替代人工核验。

### 趋势/短线加仓分支

用户明确要求短线、趋势、技术或量价操作时，不强行套用个股 QARP 估值、TTM 净利和两份研报流程；ETF 尤其应以指数趋势、量价和组合风险为主。按以下顺序执行：

1. 读 `PORTFOLIO.md`，确定现有股数、仓位、同币种现金和行业暴露。
2. 拉最新盘口与至少 120 根日线；标准 daily 为空时，降级使用 QQ Finance `fqkline` 日线和 `minute/query` 分时，并以实时 quote 核对价格、成交额和时点。只把成功返回的数据写入结论，不记录瞬态失败。
3. 计算 MA5/10/20/60、5/10/20日均量、当日量比、近5/10/20日涨跌、OBV方向、日内VWAP；标出最近摆动高低点和密集成交区。
4. 把“盘中触发”和“收盘确认”分开：盘中越过压力位不算突破；优先要求收盘站稳、成交量达到20日均量约1.2倍，再等下一交易日回踩不破。直接高开或急拉到下一压力区时放弃追价。
5. 同时给两条互斥路径：突破回踩买入，或缩量回踩支撑买入。每条都写死价格区间、成交量条件、买入股数、预计金额、买后仓位和失效位。
6. 新增趋势仓与原有底仓分开管理；趋势仓触发失效位时先退出新增部分，不因一次失败机械卖出中期底仓，也不在失效位下继续摊平。
7. 遵守用户默认分2–3次、每次至少间隔1周的节奏；单次动作通常只把仓位提升约0.5–1个百分点，并保留手续费和现金缓冲。

## 加仓前必须过的四道关

### 1. 表观利润失真剥离（先做，否则后面全错）

净利大跌不等于经营恶化。逐项剥离后再判断：汇兑损益（非现金）、关税/退税一次性、保险赔款、资产处置、政府补助。**剥离前后各写一遍增速**，并明确哪个口径进入估值。

判据：剔除干扰项后毛利率与经营现金流仍改善 → 质量端未坏，问题只在价格；剔除后仍恶化 → 直接进减仓框架，不谈加仓。

经营现金流/归母净利 >100% 且净负债接近零，是「表观利润被会计项压低」的强佐证。

### 2. 价格分位 ≠ 估值分位（最容易骗自己的一步）

估值脚本的「历史分位」常是**价格代理**，不是 PE 分位。盈利被下修后，价格分位与 PE 分位会背离到相反方向。

规则：引用价格位置时，5年与52周窗口必须分列，明确它们不是估值分位。历史PE/PB分位也只是参照，不能由“价格分位高＋PE分位低”机械推出持有；最终以同口径可持续盈利、现金流、内在价值和目标回报判断。用户只问价值时，不必在正文堆砌价格分位。

### 3. 卖方共识分歧折价

汇总每家券商的 EPS 预测与目标价，按机构独立性去重（同一机构 A/H 两版算一份）。目标价打折系数、分歧度对应的安全边际加成、分标的最低安全边际，一律以 `inv-qarp-strategy` 的「卖方乐观偏差修正」「分歧度信号」与安全边际表为准，不在此重复数值。

- 全体机构同向下修 EPS 是明确的「不加仓」信号，即便评级仍是买入——评级滞后于模型。
- 按 QARP 规则打折取中位数后，相对现价空间不足 15% 就不要找理由建仓，写成观察 + 触发条件。

### 4. 现金与机会成本闸门

按用户当前现金规则核算实际购买力，不套固定5%现金底线：用户允许工资流入自然补充、但不允许透支。分别测算“现有可用同币种现金＋部分卖出”和“完全由卖出筹资”，保留汇差与费用缓冲；不把美元现金自动视为可立即用于人民币或港币交易。

用户指定卖出标的时，优先比较该标的与拟买入标的的保守回报，而不是另找低PE股票替代问题。把“拟买标的更划算”和“它已达到绝对回报要求”分成两个判断；证据不足时只能表达偏好，不能断言未来必然跑赢。指数滚动会计PE与个股预测调整后PE不能直接相除得出便宜倍数。

用终值盈利、退出倍数、分红与汇率情景计算持有期IRR，再反推满足目标回报的买价。将参考买价明确标为假设条件下的结果，而非精确内在价值或价格必然触及的点位；区分当前内在价值与未来退出价值，不用未来目标价直接计算当前安全边际。

## 常见陷阱

- **不要用「逻辑没坏」推出「可以加」**。逻辑未坏只解除卖出，不构成买入理由；缺的是价格。
- **不要把购买力改善当作估值改善**。工资到账或卖出筹资只解决资金来源，不改变买入价格与预期回报。
- **不要把卖方目标价当买入纪律**，也不要因目标价不变就推断盈利预测没变（估值基期滚动会掩盖下修）。
- **中文标的名检索有分词歧义**，web_search 时加引号或配代码/英文名。
- 只有现金变动（工资流入、分红到账）时，仓位是被动摊薄：更新 PORTFOLIO.md 的总资产、现金、纪律检查三处，并在调仓记录写明「无买卖」，不要改股数。
- **卖方链内排序要看全**：建银国际等机构常给出"零部件 > OEM"的链内排序；引用牛方覆盖时必须同时点出其链内定位，避免把"中国 OEM 首选"误读为全链首选。
- **出口期权定价**：目标市值中若含大额"出口期权"（如 25 台燃机 × 高毛利），该部分可白拿不应付钱买；安全边际测算须基于核心业务可持续净利，期权部分单独列出。
- **公告接口失败降级**：`cs_stock_info.py announcements <A股代码>` 失败（exit≠0）时，降级为交易所公告（上交所/巨潮）或 web_search 带引号+代码检索，不得跳过 A 股近期事件核查。
