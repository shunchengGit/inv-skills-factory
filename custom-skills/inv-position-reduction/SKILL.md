# 仓位缩减决策框架

## 适用场景

不是逻辑破坏，不是估值透支——只是公司质量不错，但**仓位给得太多了**，或者**现金实在太少**。

这是最常见的组合管理操作，也是最容易被行为偏差扭曲的操作。

---

## 本用户的调整决策顺序

- 先确认风险承受、账户外家庭备用金、未来用款期限和换仓偏好；优先使用逐项单选，不在未确认时把“现金少/仓位高”直接等同于需要卖出。
- 用户已表达：能承受逻辑未坏时的较大价格波动，家庭备用金充足、三年基本不动用投资账户；替代机会经保守同口径比较有明显优势时愿主动换仓，不受成本价影响。后续以最新用户声明为准。
- 因此优先比较未来回报与逻辑失效风险，不为降低波动机械减仓，也不为长期持有而拒绝机会成本换仓。个人硬上限仍须遵守，但上限不等于目标仓位。
- 成本价不决定资产吸引力，却可能影响实现收益税费；账户通道可择优不等于可忽略税收居民申报。基于收益优势的卖出，不应一概称为承认原仓位管理失误。

## ETF去留：先确认投资命题，再评估工具与价格

- 用户说“买入逻辑不清楚”时，不直接推导为“不再需要配置”并建议清仓。先用单选确认：不再看好行业、仍看好但工具不匹配、担心估值、或需要补研究。长期命题、工具适配、价格吸引力是三个不同判断。
- 本用户长期看好中国AI及人形机器人零部件，尤其减速器、执行器、灵巧手、传感器；以最新声明为准。不能将泛科技等同AI，将工业自动化/扫地机器人等同人形零部件，也不能因共同科技风险就机械退出。
- 工具研究不足不等于资产差，行业看好也不等于立即买入。改变建议时明确新增事实与原判断错误，避免随着用户表达在“卖出—保留—买入”间迎合式反转。
- ETF穿透、官方资料取证、同指数工具比较与交易门禁见 `references/thematic-etf-fit-and-exit.md`。

## 检查清单

| 问题 | 说明 |
|------|------|
| 公司逻辑是否破坏？ | 若破坏 → 按卖出条件处理，不是减仓 |
| 估值是否透支？ | 若透支 → 按卖出条件分批减仓 |
| 问题是仓位太大，还是公司不好？ | 前者减仓，后者清仓 |
| 减了之后换什么？ | ① 补现金 ② 加更优标的 ③ 降行业集中度 |
| 有浮亏，割得下手吗？ | 沉没成本不是决策依据。唯一问题是：**未来哪个回报更高？** |
| 减多少？ | 根据目标仓位反算，目标仓位 = 该质量公司应配的合理仓位上限 |

## 减仓量测算

```
减仓股数 = (组合总资产 × (当前仓位 - 目标仓位)) / (当前价 × 报价币种兑组合基准币种汇率)
# 仓位用小数；价格与总资产必须同币种。卖出资金留在账户、暂不计费用时适用。
# 按交易单位取整后重算总资产、现金与仓位；有提现、税费或同时买入时应联立重算。
释放现金 = 减仓股数 × 当前价
实现亏损 = 减仓股数 × (成本价 - 现价)  ← 这是买贵了的代价，不是公司判断错的代价
```

**示例一**（来自 2026-06-24 会话：福耀玻璃调仓决策）：
- 福耀 4,600 股，成本 ¥60.5，现价 ¥49.25，仓位 23.9%
- 目标仓位 15%，应减至 ~2,900 股
- 减 1,500 股 → 释放 ~¥7.4 万，实现亏损 ¥16,875
- 效果：福耀 23.9% → 14.9%，现金 1.3% → 9.1%
- 判断：公司逻辑未破坏（全球汽车玻璃龙头），但 TTM PE 18.8x 对个位数增长公司偏贵，仓位过大，现金严重短缺。减仓正确。

**示例二**（来自 2026-07-17 会话：腾讯与整体杠铃校验调仓）：
- 腾讯 900 股，现价 HK$484.0，持仓占比 37.1%（逼近 40% 单只上限），导致“软件/互联网”行业集中度达到 55.9%（超出 55% 限制），且组合现金仅 1.8%（低于 2% 警戒线）。
- 调仓方案：减持 100 股腾讯（仓位 37.1% → 约 33.0%）。
- 释放资金：约 4.84 万港元（约合 4.18 万元人民币），使整体现金比率回升至 5.9% 理想区间。
- 判断：公司基本面无恶化（Weixin Agent 公测开启），但为解决行业超限及组合现金极度匮乏，必须被动调整，增厚防御端。

## 资金流向优先级

1. **先满足用户最新硬约束**：现金、单股和行业上限以最新 USER.md 为准，不把经验性“理想区间”冒充违规红线。
2. **建立现金缓冲**：若用户希望增加现金，再买入必须按卖出与买入的净效果复核，避免名义补现金、实际换仓。
3. **降行业集中度**（若该行业已接近上限）。
4. **加仓更优标的**：只有当现金充足，且B的预期回报/证据质量明显优于A，才做卖A买B。

## 卖出补现金后又拟加仓：必须穿透成一笔换仓

当用户先问“卖A增加现金”，随后又问“B能否加仓”时，不得割裂回答：

1. 读取最新组合，计算三种情景：不操作、只卖A、卖A后买B。
2. 分别列出现金比例、A/B仓位、行业集中度；若买B吃掉刚补出的现金，明确称为“换仓”而非“增加现金”。
3. 比较A与B：企业质量、估值安全边际、证据新鲜度、打脸条件和组合角色。B只有显著更优才值得换。
4. 若B在近一个月刚连续增持，默认提高再交易门槛，优先等待财报、订单、现金流等事先设定的验证条件，防止行动偏误和调仓过频。
5. 给出条件式结论：`if 价格/基本面验证条件满足 then 最小一批 else hold`；禁止仅因“仓位还小”就建议加仓。
6. 对周期/重装股，价格分位必须用最新历史日线重算；旧报告中的“52周低位”不能沿用。估值便宜也需同时核验订单覆盖率、扣非利润和FCF。

具体测算模板见 `references/cash-replenishment-and-redeployment.md`。

## 跨行业三年持仓比较：先统一期限，再判断是否值得换仓

- 对两股统一买入估值日、退出日和计息年数；明确2029全年盈利作为退出时的前瞻估值锚，并不把退出日延长到2029年末。报告期净资产、起点净资产代理和期末前瞻净资产不得混称。
- 银行用**普通股BVPS—ROE—资本约束**，排除优先股/永续债权益；不套制造业FCF门槛。电力重装用**订单签约→交付→扣非盈利→回款、周期PE及可分配净现金**，不用PEG。账面现金扣债不等于可分配现金，财务公司存款、受限款和履约资金需穿透，不能直接加到PE估值上。
- 熊中牛逐项列EPS或BVPS、期末PE/PB、持有期实收股息、币种/汇率及来源；区分官方事实、卖方预测、自建假设。两家独立研报原文不等于两家最新个股盈利模型，行业报告不能替代财报后模型。反方原文中的“维持”与“下调”、HoH与QoQ必须准确区分。
- 按用户要求实际执行估值并交付Markdown及JSON；门禁缺失写未知或null，不把条件测算写成可交易结论。截止时间前核验进程退出状态、输出非空、JSON可解析，并使文件与最终回复的失败/降级状态一致。
- 实践检查表见 `references/three-year-cross-sector-comparison.md`。
- 换仓前必须做财年日历化、分红收现、估值/汇率排序反转测试；AH折价持续时不默认赚取收敛收益。详见 `references/rotation-robustness-and-cross-listing.md`。

## 成熟业务＋新业务期权：换仓比较的额外门槛

- 用户要求人形机器人等新产业机会时，先拆已有业务与新增业务，不以主题更纯、产业位置更重要代替价格吸引力。已有工业机器人收入不能再次当新增人形收入；总EPS已含新业务时不得重复叠加。
- 市值减已有业务价值仅为“未被基础模型解释的溢价”，可能含液冷、其他增长、估值误差；不能因果归为全是机器人。必须同时测算“解释今天价格”与“整笔投资达到目标回报”，两者不是同一门槛。
- 正常化利润、分部费用、可分配现金未核实时，只做明确标注的区间压力测试，不把人为设定的熊/中/牛利润当预测，更不能用极端情景收益率证明某股必然下跌。
- 跨股类使用相应买入价乘全股本的等价估值比较每股权益，另列真实A/H合计市值；不默认AH折价收敛。研究排序与可执行换仓结论分开。
- 反向估值公式、交付证据分级及复核清单见 `references/incumbent-business-and-new-business-options.md`。

## 浮亏减仓的心理纪律

浮亏减仓可能来自风险预算调整、机会成本变化或原判断被证伪，不能一概归为仓位管理失误。先判断未来收益、风险和替代机会，再说明是否存在需要复盘的错误。

| 行为陷阱 | 表现 | 应对 |
|----------|------|------|
| **锚定效应** | "等涨回成本价再减" | 成本价是历史，不是未来。只问：这个价钱这个仓位合理吗？ |
| **后悔厌恶** | "割了就真亏了" | 已经亏了。不操作并不能让亏损消失。操作是为了让未来更好。 |
| **行动偏误** | "必须做点什么" | 如果最合理的操作是补现金，那就补现金，不需要换成一个新标的。 |
| **高抛低吸幻觉** | "等反弹到X再减" | 如果仓位过大，现在就该减。等反弹是择时，择时不如纪律。 |

## 与 QARP 卖出条件的衔接

| 场景 | 操作 | 参考 |
|------|------|------|
| 逻辑破坏 | 一次性卖出 | 按 QARP 卖出条件 |
| 估值透支 | 分 2-3 次减仓 | 按 QARP 卖出条件 |
| **仓位过大 + 公司不错** | 减至目标仓位，补现金优先 | 本框架 |
| **换仓**（卖出A→买入B） | 先按本框架减A，现金到位后再看B | 本框架 + QARP 买入规则 |
