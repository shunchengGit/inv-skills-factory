# QARP 知识库深度搜索协议

本协议把 `inv-knowledge-curator` 的通用 L2/L3 挖掘转换为 QARP 决策证据链。目标不是“找到几篇研报”，而是回答：增长来自哪里、质量能否延续、市场在担心什么、什么事实会打脸、当前价格是否补偿了不确定性。

## 一、深度选择

| 场景 | 最低深度 | 升级条件 |
|---|---|---|
| `/qarp_screen` | L1+ | 闸门证据冲突或仅单一来源时升级 L2 |
| `/qarp` 新标的 | L2+ | 首次覆盖、周期股、争议大、目标价分歧 >1.5x、知识缺口影响估值时升级 L3 |
| `/qarp_check` 已有持仓 | L2 | 出现打脸信号、财报后重大变化或计划调仓时升级 L3 |
| 机会成本对比 | 每个候选至少 L1+ | 两者结论接近时，对关键替代标的升级 L2 |

L2+ 表示完整 L2，并强制加入时间线、反向回链和原文回溯。任何“买入/加仓/减仓/卖出”建议不得只基于 L1。

## 二、检索矩阵（必须实际执行并记录）

先读 `entries/index.md`，再对 `entries/*.md` 做多角度搜索。中文名、英文名、代码分别检索，避免漏召回。

| 证据篮子 | 关键词组合示例 | 流入环节 |
|---|---|---|
| 标的直达 | `{中文名}`、`{英文名}`、`{代码}` | 候选全集 |
| 行业空间 | `{行业} TAM`、`渗透率`、`CAGR`、`需求`、`订单` | 第一道闸门 |
| 竞争与护城河 | `{标的} 竞争`、`市占率`、`competitive-advantage`、`moat`、`替代` | 第一道闸门 |
| 财务质量 | `{标的} 毛利率`、`ROE`、`FCF`、`现金流`、`资本开支` | 第二道闸门 |
| 盈利预测与估值 | `{标的} EPS`、`盈利预测`、`目标价`、`valuation`、`PE` | 五档/估值纪律 |
| 风险与反方 | `{标的} 风险`、`下调`、`低于预期`、`bear`、`downgrade`、`risk-factor` | 打脸条件 |
| 管理层与资本配置 | `{标的} 管理层`、`回购`、`分红`、`激励`、`资本配置` | 第三道闸门 |
| 催化与时间线 | `{标的} 财报`、`订单`、`指引`、`NDR`、季度标签 | 观点变化 |

最低要求：新标的完整分析至少覆盖 6 个证据篮子；持仓检查至少覆盖标的直达、财务质量、盈利预测、风险反方、催化时间线 5 个篮子。禁止把一次宽泛搜索计作多个角度。

## 三、候选筛选与来源独立性

1. 建候选清单：记录 path、type、timestamp、source_type、机构、resource、命中篮子。
2. 去重：同一条目、同一 PDF 的二次摘要、同一机构同日快评视为一个来源。
3. 分层读取：`Reference > Synthesis/Analysis > Article`；但最终判断必须回到财报事实或原始研报。
4. 来源独立性：至少 2 家不同机构才能称“卖方共识”；同一券商多篇只能证明观点延续，不能提高独立来源数。
5. 多空平衡：主动找至少 1 条反方、下调或风险证据。找不到时标注“反方覆盖缺口”，不得写“市场无重大担忧”。

## 四、关联链、标签与双向回链

对 3-5 个核心条目执行：

1. 跟随其 `## 关联` 至少 1 层；首次覆盖或 L3 跟随第 2 层。
2. 浏览至少 2 个关键 `entries/by-tag/{tag}.md`，通常为标的标签 + 决策维度标签（如 `valuation`/`risk-factor`）。
3. 对核心 slug 做反向检索：搜索 `slug.md`，找出谁引用了该条目。
4. 将间接命中按“补充/冲突/过时”分类，不机械扩大阅读量。

完成标准：报告中列出“直接命中数、关联扩展数、反向回链数、最终采用数”。

## 五、时间线与观点漂移

按日期排列关键证据，至少覆盖最早基准、最近财报/研报和中间一次变化（若库内存在）：

| 时点 | 来源 | 指标/观点 | 相比前次 | 对 QARP 的影响 |
|---|---|---|---|---|

必须判断：
- 盈利预测、目标价、评级是上修还是下修；
- 毛利率、订单、FCF、资本开支等关键变量是否改善；
- 券商观点变化来自基本面、估值还是市场情绪；
- 旧结论是否已被新财报证伪。

禁止把不同日期的预测拼成“当前共识”。最新事实优先，历史条目只用于观察变化。

## 六、原始研报回溯（强制配额）

使用：

```bash
python3 /Users/chengshun/.hermes/skills/inv-skills/inv-knowledge-curator/scripts/km_import.py read \
  --file /Users/chengshun/.inv-knowledge/{resource} --pages edges
```

`--file` 必须是 `/Users/chengshun/...` 绝对路径或以 `res/` 开头。若 `resource` 为列表，逐项选择最相关 PDF，不把列表拼成一个参数。

最低配额：
- `/qarp`：至少回溯 2 份原始资源，优先“最新核心研报 + 关键反方/分歧研报”；库内仅 1 份时回溯该 1 份并标注覆盖不足。
- `/qarp_check`：至少回溯 1 份最新、与打脸条件最相关的资源；若计划调仓则至少 2 份。
- `/qarp_screen`：通常不强制；若仅靠单篇摘要决定不通过，回溯原文确认。

以下情况无论配额均必须回溯：具体数字影响估值、摘要省略假设或风险、条目之间数字冲突、目标价/评级发生变化、需要引用管理层原话。

每个关键数字记录：数值、口径、预测期、原始资源路径、页码/首尾页位置（可得时）。无法定位则标注“摘要级证据”，不得伪装成原文核验。

## 七、证据矩阵与冲突裁决

最终采用的关键结论必须进入证据矩阵：

| 命题 | 财报/行情事实 | 来源A | 来源B/反方 | 时效 | 强度 | 冲突处理 | 流入决策 |
|---|---|---|---|---|---|---|---|

强度规则：
- 强：财报事实 + ≥2 个独立来源一致；
- 中：财报事实 + 1 个来源，或 ≥2 个卖方独立来源一致；
- 弱：单一来源、摘要级、无法被事实验证；
- 冲突：来源方向相反，必须解释分歧变量，不做平均化处理。

裁决顺序：最新已披露事实 > 公司正式指引 > 多个独立卖方预测 > 单一卖方预测 > 二手文章。目标价不参与事实裁决。

## 八、覆盖门禁

输出结论前检查：

- [ ] 达到对应检索篮子数量；
- [ ] 至少 2 个独立来源（库内确实不足时明确降级）；
- [ ] 已追踪关联链并浏览标签；
- [ ] 已执行反向回链；
- [ ] 已构建时间线并识别观点漂移；
- [ ] 达到原始资源回溯配额；
- [ ] 至少主动寻找 1 条反方证据；
- [ ] 关键数字有口径、预测期和来源；
- [ ] 已输出知识缺口及其对估值/仓位的影响。

若影响核心结论的项目未通过：`knowledge_status=insufficient`，只允许“继续研究/观察”，不得给买入或加仓建议。若仅非核心维度不足：`knowledge_status=partial`，降低置信度和仓位上限。全部通过：`knowledge_status=ok`。

## 九、结构化输出

知识库部分必须先于三道闸门输出：

1. 检索审计：深度、关键词篮子、直接/扩展/反链/采用数量、来源机构数、日期窗口；
2. 覆盖度表：行业、竞争、财务、估值、风险、管理层、催化；
3. 时间线与观点漂移；
4. 共识、分歧、反方和卖方盲点；
5. 原始资源回溯清单；
6. 证据矩阵；
7. `knowledge_status` 与缺口对决策的影响。

只列“读了哪些文章”不算完成；每条证据必须映射到闸门、估值纪律、打脸条件或仓位判断。
