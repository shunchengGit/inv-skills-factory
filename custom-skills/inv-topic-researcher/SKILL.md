# inv-topic-researcher：投资主题信息采集框架

多源信息采集与加工框架。不是简单的“搜索→入库”，而是按来源优先级逐层采集、交叉验证、产出综合摘要，并整理成可移交 `inv-knowledge-curator` 的待入库建议。

## 命令
| 命令 | 用途 |
|------|------|
| `/research <主题>` | 全流程：编排 → 采集 → 验证 → 综合 → 交付待入库建议 |
| `/research <主题> --quick` | 快速模式：跳过阶段一（L3 全库挖掘），仅 Web 搜索。⚠ 信息完整性下降，不使用知识库已有分析 |
| `/research <主题> --refresh` | 刷新模式：针对已研究过的主题，输出增量研究与待更新建议 |
| `/research <主题> --landscape` | 行业全景模式：web-first 广度扫描，多标的对比+持仓交叉 |

## 来源优先级
**永远先本地、后外部。** 每个来源层能回答的问题不同，跳过某一层意味着放弃某种质量的信息。

```
┌─ 第 0 层：本地已有（L3 全库挖掘）──────────────────────────┐
│  inv-knowledge-curator 深度挖掘：多角度搜索 + cross_refs   │
│  遍历 + 标签导航 + 聚合分析 + 知识缺口评估                  │
│  能回答：卖方怎么看？我们之前收集了什么？还缺什么？          │
├─ 第 1 层：一手源 ─────────────────────────────────────────┤
│  SEC EDGAR (sec.gov)、港交所披露易 (hkexnews.hk)           │
│  公司 IR 页、财报电话会议记录、监管文件                     │
│  能回答：公司自己说了什么？事实是什么？                      │
├─ 第 2 层：二手分析 ───────────────────────────────────────┤
│  WebSearch → 财经媒体、行业报告、分析师评论                  │
│  能回答：市场怎么看？有何分歧？                              │
└──────────────────────────────────────────────────────────┘
```

## 全流程
### 阶段一：查知识库（研报已纳入知识库，一个入口，主题研究默认 L3）

- 按 `inv-knowledge-curator/references/deep-mining-protocol.md` 的 **L3 全库挖掘**执行。
- 本技能只补充两点：
  1. 主题研究默认覆盖标的/估值/风险/行业/竞争等多角度，并输出知识库覆盖度矩阵。
  2. 条目摘要不足以支撑结论时，可用 `km_import read --file <res/...pdf> --pages edges` 回溯原始 PDF。
- 输出：已有画像（已知什么 + 缺什么 + 已有信息的最晚时点 + 知识库覆盖度矩阵），其中“缺口”直接作为阶段四输入。
- **只读边界**：本技能对知识库只读，仅使用 `/km_search` + `km_import read`；不调用知识库写入口。


### 阶段二：一手源采集（抓事实，不抓观点）

根据标的市场选择一手源：

| 市场 | 一手源 | 抓取内容 |
|------|--------|---------|
| 美股 | sec.gov, 公司 IR 页 | 10-K/10-Q 关键章节、Earnings Call Transcript、8-K 重大事项 |
| 港股 | hkexnews.hk, 公司 IR 页 | 年报/中报、关联交易公告、回购/增持披露 |
| A股 | 巨潮资讯 (cninfo.com.cn) | 年报/中报、重大事项公告、调研记录 |

Agent 用 WebFetch 抓取，每个来源控制在 **1-3 个页面**（只抓最相关的，不全量爬）。

```
对每个一手源页面：
  1. WebFetch → 提取关键事实（数字、日期、官方表述）
  2. 标注来源层级：一手源 / 官方公告
  3. 标注数据时点：{发布日期，精确到日}
```

### 阶段三：二手分析采集（Web 搜索）

使用 Agent 可用的 Web 搜索工具，按以下优先级：

```
可用工具检测 → 搜索（多角度，见搜索策略）→ 去重 → 预过滤 →
  → 抓取页面内容 → 相关性门控 → 新鲜度门控 → 可靠性门控 →
  → 分析
```

**工具选择**：如果当前环境有 Firecrawl MCP（`firecrawl_search` + `firecrawl_scrape`），优先使用（搜索结果含全文提取、反爬处理更好）；否则用 Agent 内置 WebSearch + WebFetch。Firecrawl 环境下搜索完成后调用 `firecrawl_search_feedback` 反馈搜索质量。

搜索策略、新鲜度窗口、可靠性信号、源层级表、已知反爬站/低质量源名单 — 见下文「参考附表」。

### 阶段四：缺口分析与定向补充

以阶段一的“已有画像”为基线，收集完三层素材后检查信息空白是否已填补。缺口分析表与补充动作模板见 `references/output-and-tables.md`。

### 阶段五：交叉验证

**多源对照**：对同一事实或判断，对照不同来源的一致性。这是整个流程最关键的一步。交叉验证模板与一致性表示例见 `references/output-and-tables.md`。

### 阶段六：综合摘要

产出**一份**主题综合报告（Markdown），模板详见 `references/output-and-tables.md`。

### 阶段七：交付待入库建议

输出结构化交付包，供后续人工审核或交由 `inv-knowledge-curator` 主流程入库：
- 事实层候选：一手源/客观事实条目建议（`tags: [primary-source]`）
- 分析层候选：二手分析与交叉验证后的判断（`tags: [analysis]`）
- 综合层候选：主题综合报告（`tags: [synthesis]`）
- 每个候选项至少附：建议标题、日期、来源清单、候选 tags、是否建议回溯原文

### 阶段八：刷新研究输出

用 `/km_search` 找上次相关综合条目或研究输出获取基线 → 只补充基线时点后的新信息 → 对比新旧 → 输出增量研究与待更新建议。若需要真正落库或版本递增，由 `inv-knowledge-curator` 主流程执行。
## 输出格式与参考附表

详见 `references/output-and-tables.md`，包含：
- 输出模板
- 搜索模板表
- 缺口分析表
- 交叉验证模板表
- 终止条件与异常处理

> `--quick` 模式跳过阶段一，仅执行阶段三到七；`--refresh` 模式执行阶段八。

## `--landscape` 行业全景扫描模式

web-first 广度优先的行业/产业链扫描，适用于"还能买什么/行业筛选/板块对比"。详细工作流、输出模板、顺序钻取模式、分析师降级方案见 `references/landscape-scan-workflow.md`。

| 维度 | deep-dive | landscape |
|------|:---------:|:---------:|
| 信息源顺序 | 本地→一手→二手 | Web-first 广度优先 |
| 标的数量 | 1-2 个 | 3-10 个 |
| 交付方式 | 待入库建议 + 综合报告 | 一次性对比报告 |
| 产出 | 综合报告 + 候选条目清单 | 对比表 + 优先级排序 |

## 依赖

- `inv-knowledge-curator` — 知识库搜索/导入/健康度检查（/km_search /km_import /km_lint）
- `inv-portfolio-tracker` — 持仓数据（landscape 模式交叉分析用）
- Agent WebSearch — 多角度搜索
- Agent WebFetch — 网页抓取（一手源 + 二手分析）
