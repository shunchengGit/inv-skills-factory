# inv-topic-researcher：投资主题信息采集框架

多源信息采集与加工框架。不是简单的"搜索→入库"，而是按来源优先级逐层采集、交叉验证、产出综合摘要后分层入库。

## 命令

| 命令 | 用途 |
|------|------|
| `/research <主题>` | 全流程：编排 → 采集 → 验证 → 综合 → 入库 |
| `/research <主题> --quick` | 快速模式：跳过本地检查，仅 Web 搜索 |
| `/research <主题> --refresh` | 刷新模式：针对已研究过的主题，增量更新 |
| `/research <主题> --landscape` | 行业全景模式：web-first 广度扫描，多标的对比+持仓交叉 |

## 来源优先级

**永远先本地、后外部。** 每个来源层能回答的问题不同，跳过某一层意味着放弃某种质量的信息。

```
┌─ 第 0 层：本地已有 ──────────────────────────────────────┐
│  inv-research-analyzer（券商研报 PDF）                     │
│  知识库 km_search（知识库已有条目，外部工具）                │
│  能回答：卖方怎么看？我们之前收集了什么？                    │
├─ 第 1 层：一手源 ─────────────────────────────────────────┤
│  SEC EDGAR (sec.gov)、港交所披露易 (hkexnews.hk)           │
│  公司 IR 页、财报电话会议记录、监管文件                     │
│  能回答：公司自己说了什么？事实是什么？                      │
├─ 第 2 层：二手分析 ───────────────────────────────────────┤
│  WebSearch → 财经媒体、行业报告、分析师评论                  │
│  能回答：市场怎么看？有何分歧？                              │
└──────────────────────────────────────────────────────────┘
```

## 全流程

### 阶段一：本地检查（先问自己有什么）

```
1. 查本地研报
   → inv-research-analyzer: research_pdf.py list --contains <关键词>
   → 有 → 提取核心观点（共识/分歧/盈利预测/风险）
   → 无 → 标注"本地无研报"

2. 查知识库
   → km_search.py <关键词>（外部工具）
   → 有 → 提取已有条目摘要，标注数据时点
   → 无 → 标注"知识库无记录"

输出：本地画像（已知什么、缺什么、已有信息的最晚时点）
```

### 阶段二：一手源采集（抓事实，不抓观点）

根据标的市场选择一手源：

| 市场 | 一手源 | 抓取内容 |
|------|--------|---------|
| 美股 | sec.gov, 公司 IR 页 | 10-K/10-Q 关键章节、Earnings Call Transcript、8-K 重大事项 |
| 港股 | hkexnews.hk, 公司 IR 页 | 年报/中报、关联交易公告、回购/增持披露 |
| A股 | 巨潮资讯 (cninfo.com.cn) | 年报/中报、重大事项公告、调研记录 |

Agent 用 WebFetch 抓取，每个来源控制在 **1-3 个页面**（只抓最相关的，不全量爬）。

```
对每个一手源页面：
  1. WebFetch → 提取关键事实（数字、日期、官方表述）
  2. 标注来源层级：一手源 / 官方公告
  3. 标注数据时点：{发布日期，精确到日}
```

### 阶段三：二手分析采集（Web 搜索）

复用 WebSearch + WebFetch，保持已有的三重门控：

```
搜索（多角度，见搜索策略）→ 去重 → 预过滤 →
  → WebFetch → 相关性门控 → 新鲜度门控 → 可靠性门控 →
  → 分析
```

搜索策略、新鲜度窗口、可靠性信号、源层级表、已知反爬站/低质量源名单 — 见下文「参考附表」。

### 阶段四：缺口分析与定向补充

收集完三层的素材后，检查是否还有信息空白：

| 缺口类型 | 检查方式 | 补充动作 |
|---------|---------|---------|
| 事实缺口 | 是否有最新季度数据？关键经营指标是否完整？ | 定向搜索指定指标 |
| 观点缺口 | 是否有看多和看空两种视角？ | 搜索"bear case"或"short thesis" |
| 时效缺口 | 最新一条信息距今是否超过窗口？ | 搜索时加当前月份 |
| 风险缺口 | 是否覆盖了监管/地缘/竞争/技术颠覆风险？ | 逐项搜索 |

> 缺口分析产出一张对照表，标注每项的覆盖状态（✅ 已覆盖 / ⚠ 不完整 / ❌ 空白）。

### 阶段五：交叉验证

**多源对照**：对同一事实或判断，对照不同来源的一致性。这是整个流程最关键的一步。

```
对每个关键判断（营收增速、市场份额、目标价、行业趋势）：
  来源 A（卖方研报，2026-03）：$150 目标价，假设 15% 增速
  来源 B（公司指引，2026-02）：10-12% 增速
  来源 C（财经媒体，2026-04）：行业平均 8%

  → 标记：卖方乐观偏差 +5pp vs 公司指引，需打折使用
  → 输出：一致性评价（共识 / 有分歧 / 矛盾）
```

交叉验证输出格式：

| 判断点 | 来源 A | 来源 B | 来源 C | 一致性 |
|--------|--------|--------|--------|:--:|
| 营收增速 | 卖方 15% | 公司 10-12% | 行业 8% | 🔴 分歧 |
| 竞争格局 | 护城河稳固 | 份额下降 | — | 🟡 有争议 |
| 估值中枢 | PE 18x | PE 19x | PE 17x | 🟢 共识 |

### 阶段六：综合摘要

基于所有采集的素材，产出**一份**主题综合报告（Markdown），不替代各条目，而是提供俯瞰视角。

```
# 主题综合报告：{topic}
> 研究时间：{timestamp} | 来源：{N 份研报 + M 条一手 + K 条二手}

## 关键事实（来自一手源，非观点）
- 2026Q1 营收 $12.3B，YoY +11%
- FCF $2.1B，CapEx 占营收 22%
- 宣布 $5B 回购计划（2026-04-15 公告）
...

## 市场共识
- 卖方一致预期：FY2026 营收增速 8-10%，EPS $4.50-5.00
- 目标价区间：$120-160（中位数 $138）

## 关键分歧
- 增速假设：卖方 15% vs 公司指引 10-12%（卖方偏乐观）
- AI 投入回报：看多认为 2027 年进入回报期，看空认为 CapEx 无底洞

## 风险清单（按来源标注）
| 风险 | 来源 | 严重度 |
|------|------|:--:|
| 地缘政治导致供应链中断 | 卖方研报 + 公司 10-K | 高 |
| AI 投入从被奖励转为被惩罚 | 财经媒体（2026-04） | 中 |
| 新进入者价格战 | 行业报告 | 低 |

## 信息覆盖度
| 维度 | 状态 | 说明 |
|------|:--:|------|
| 财务数据 | ✅ | 最新 Q1 数据已获取 |
| 竞争格局 | ✅ | 多源交叉验证 |
| 管理层评价 | ⚠ | 仅卖方研报提及，无一手访谈 |
| 政策风险 | ❌ | 未找到实质性分析 |
```

### 阶段七：分层入库

不是把所有东西一股脑塞进 knowledge base。按信息层级分三类存储：

| 层级 | 内容 | 存储方式 | 示例 |
|------|------|---------|------|
| **事实层** | 一手源提取的客观数据 | 单条目，`tags: [primary-source]` | 财报关键数字、官方公告摘要 |
| **分析层** | 二手分析的论证和判断 | 单条目，`tags: [analysis]` | 卖方研报观点、媒体深度文章 |
| **综合层** | 阶段六的综合报告 | 单条目，`tags: [synthesis]`，frontmatter 中关联各来源条目 | 主题综合报告 |

> 综合层条目标题格式：`综合报告：{topic}（{YYYY-MM-DD}）`
> km_import 入库后，综合报告记录在 Index 中，下次 `/research --refresh` 时自动找到上一次的综合报告作为基准。

### 阶段八：刷新机制

`/research <主题> --refresh` 专门用于更新已研究过的主题：

```
1. km_search 找到上一次的综合报告 → 获取基线（上次数据时点、关键事实、共识）
2. 只搜索"基线时点之后"的新信息（WebSearch 加 since:YYYY-MM-DD 或最近 N 个月）
3. 对比新旧信息：
   - 哪些判断仍然成立？
   - 哪些数据已经过时？
   - 有什么新风险/新事件？
4. 更新综合报告 → 版本号递增（v2, v3 ...）
5. ⚠ 不删除旧版本，新旧并存，通过 km_search 可追溯演进
```

## 搜索策略（阶段三用）

**多角度覆盖**：一个主题至少 2-3 个角度搜索，合并去重：

| 场景 | 搜索模板 |
|------|---------|
| 公司研究 | `"<公司名> stock analysis strategy"`、`"<公司名> earnings growth outlook"`、`"<公司名> competitive advantage moat"` |
| 行业研究 | `"<行业> industry outlook trend"`、`"<行业> market size forecast"`、`"<行业> regulation policy change"` |
| 宏观研究 | `"<主题> macro economy impact"`、`"<主题> central bank policy"` |
| 估值相关 | `"<公司> valuation DCF PE comparison"`、`"<公司> analyst target price"` |
| 风险/空头 | `"<公司> bear case risks"`、`"<公司> short thesis"` |

## 终止条件

| # | 条件 | 触发时机 | 输出 |
|---|------|---------|------|
| 1 | **综合报告完成** | 阶段六产出综合摘要 | 完整报告 + 分层入库 |
| 2 | **本地已有且无增量** | 阶段一检查后本地已全覆盖 | `本地资料充分，无需 Web 采集` |
| 3 | **连续失败熔断** | 连续 5 条 blocked/unreliable/irrelevant/stale/failed | `⚠ 搜索质量不足，建议换词` |
| 4 | **搜索无结果** | WebSearch 返回空 | 回退到本地 + 一手源已有信息出报告 |

> `--quick` 模式跳过阶段一，仅执行阶段三到七；`--refresh` 模式执行阶段八。

## 异常处理

| 异常 | 处理 |
|------|------|
| 本地研报为空 | 标注"无本地研报"，继续 |
| 知识库无记录 | 标注"知识库无记录"，继续 |
| 一手源 WebFetch 失败 | 记录，继续；一手源缺失不影响后续 |
| km_init 失败 | 警告，手动检查重复 |
| 搜索无结果 | 换关键词重试 1 次；仍无结果 → 终止条件 4 |
| 命中已知反爬/低质量源 | 直接标记跳过 |
| 内容不相关/过时/不可靠 | 按门控规则标记，继续下一条 |
| 连续 5 条不可用 | 熔断终止（条件 3） |
| km_import store 失败 | 警告，稍后重试 |
| git push 失败 | 本地已保存，稍后 `km_init` 同步 |

## 参考附表

### 新鲜度窗口

| 主题类型 | 窗口 | 原因 |
|---------|:--:|------|
| 业绩/财报 | 3 个月 | EPS、指引变化快 |
| 宏观/政策 | 6 个月 | 利率、政策方向有持续性 |
| 行业趋势 | 6 个月 | TAM、增速假设不会月月变 |
| 竞争格局 | 12 个月 | 护城河变化慢 |
| 估值分析 | 12 个月 | DCF 假设、PE 中枢长期有效 |

超出窗口 → 标记 `stale`，跳过。无法提取日期 → ⚠ 无日期，仍入库但标注。

### 可靠性信号（5 项检查）

| 信号 | 检查方式 |
|------|---------|
| 署名作者 | 是否有真实姓名作者（非 "Staff" / "Admin"） |
| 引用/数据源 | 是否引用具体数据、财报、官方文件 |
| 方法论说明 | 估值/预测是否说明了假设和计算方式 |
| 编辑痕迹 | 是否有发布日期、修订记录、事实核查声明 |
| 利益披露 | 是否有持仓披露、投行关系声明 |

缺 2 项以上 → ⚠ 低可靠性。一线源默认通过。

### 源层级表

| 层级 | 示例 | 处理 |
|------|------|------|
| 一手源 | SEC EDGAR, HKEX, 公司 IR, 巨潮 | 直接采集，最高置信度 |
| 一线财经 | ft.com, economist.com, reuters.com | 默认高置信度 |
| 二线财经 | cnbc.com, marketwatch.com, morningstar.com | 快速扫 5 信号 |
| 券商研究 | 各投行研究页面 | 方法论可靠但存在乐观偏差 |
| 低质量（跳过） | fool.com, investorplace.com, benzinga.com, simplywall.st, gurufocus.com | 直接标记 `unreliable_source` |
| 不可抓（跳过） | bloomberg.com, wsj.com, ft.com, seekingalpha.com, barrons.com, reuters.com | 直接标记 `blocked` |

## `--landscape` 行业全景扫描模式

web-first 广度优先的行业/产业链扫描，适用于"还能买什么/行业筛选/板块对比"。详细工作流、输出模板、顺序钻取模式、分析师降级方案见 `references/landscape-scan-workflow.md`。

| 维度 | deep-dive | landscape |
|------|:---------:|:---------:|
| 信息源顺序 | 本地→一手→二手 | Web-first 广度优先 |
| 标的数量 | 1-2 个 | 3-10 个 |
| 入库 | 分层入库 | 不入库，一次性报告 |
| 产出 | 综合报告+知识条目 | 对比表+优先级排序 |

## 依赖

- `inv-research-analyzer` — 本地券商研报 PDF 提取
- `inv-portfolio-tracker` — 持仓数据（landscape 模式交叉分析用）
- 知识库工具（km_search/km_import/km_lint）— 外部工具，需自行安装
- Agent WebSearch — 多角度搜索
- Agent WebFetch — 网页抓取（一手源 + 二手分析）
