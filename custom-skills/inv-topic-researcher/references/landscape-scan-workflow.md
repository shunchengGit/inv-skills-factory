# `--landscape` 行业全景扫描模式

与 deep-dive（本地优先→一手源→二手→综合入库）不同，Landscape Scan 是 **web-first 广度优先** 的工作流。

| 维度 | deep-dive (`/research`) | landscape (`--landscape`) |
|------|:-----------------------:|:--------------------------:|
| 触发 | 个股/主题深挖 | 行业/产业链/筛选 |
| 信息源顺序 | 本地→一手→二手 | Web-first 广度优先 |
| 标的数量 | 1-2 个 | 3-10 个 |
| 入库 | 分层入库到 knowledge base | 不入库，一次性报告 |
| 交叉验证 | 多源一致性评价 | 多标的对比+持仓交叉 |
| 产出 | 综合报告+知识条目 | 对比表+优先级排序 |

## 适用场景

| 场景 | 典型提问 | 产出 |
|------|---------|------|
| 行业扫描 | "美股变压器怎么样" | 行业全景+多标的对比+与持仓交叉 |
| 产业链扫描 | "AI产业链有哪些环节" | 产业链分解+各环节代表公司 |
| 行业筛选 | "电力设备板块还能买什么" | 候选列表+优先级排序 |
| 行业对比 | "HUBB vs ETN 哪个更好" | 多维度对比表 |

## 工作流

### 阶段一：理解问题范围

确定用户问的是：
- **行业全景**（如"美股变压器"）→ 先行业叙事，再个股
- **产业链环节**（如"AI电力设备"）→ 先分解环节，再各环节代表
- **对比筛选**（如"电力设备股对比"）→ 直接对比表

### 阶段二：Web 搜索 — 广度优先

与 deep-dive 的"先本地后外部"不同，Landscape Scan **先 Web 搜索建立全景**：

多角度并行搜索：
- 角度1 行业规模+趋势：`"<行业> industry outlook 2026 market size"`
- 角度2 主要玩家：`"<行业> top companies market share"`
- 角度3 投资叙事：`"<行业> AI data center investment thesis"`
- 角度4 中文视角：`"<行业> 投资分析 上市公司"`

每个角度至少 1 次搜索，合并去重。搜索返回后立即抓取最有价值的 2-3 篇。

### 阶段三：行情数据拉取（多标的并行）

确定主要标的列表后，用 `inv-stock-data` 的 `snapshot` 命令批量拉取：

```bash
export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY=http://127.0.0.1:7890

# 逐个拉取，间隔 ≥3 秒避免限流
uv run ~/.hermes/skills/inv-skills/inv-stock-data/scripts/cs_stock_info.py snapshot ETN --output json > /tmp/etn.json
uv run ~/.hermes/skills/inv-skills/inv-stock-data/scripts/cs_stock_info.py snapshot HUBB --output json > /tmp/hubb.json
```

> ⚠️ 禁止混用 A 股和美股在同一批调用中（代理状态切换必然出错）

### 阶段四：持仓交叉分析

读取 `~/.hermes/memories/PORTFOLIO.md`（通过 `inv-portfolio-tracker`），检查：

1. **已有敞口**：用户当前持有哪些相关标的？
2. **相关性矩阵**：新标的与现有持仓的行业/主题重叠度
3. **集中度约束**：新标的是否会导致单一行业超 55% 上限

输出格式：
```
| 你的持仓 | 仓位 | 与{主题}相关性 |
|----------|:----:|:--------------:|
| {标的} | {仓位}% | {高/中/低} + 原因 |
```

### 阶段五：产出综合报告

```markdown
# 投资主题研究：{topic}
> 研究时间：{timestamp}

## 一、行业大叙事：核心逻辑链
{逻辑链图 + 关键数据表}

## 二、主要标的对比
| 标的 | 代码 | 价格 | 市值 | PE-TTM | PE-Fwd | PB | ROE | 毛利率 | 营收增速 | 股息率 |
|------|------|:----:|:----:|:------:|:------:|:--:|:---:|:------:|:--------:|:-----:|

## 三、分层解读
### 🥇 第一层：{最高质量层}
### 🥈 第二层：{中间层}
### 🥉 第三层：{基础层}

## 四、关键风险
| 风险 | 描述 | 影响 |
|------|------|------|

## 五、与你的持仓交叉分析
{相关性矩阵}

## 六、初步筛选与关注顺序
{按估值纪律排序的优先级列表}

## 七、后续跟踪建议
```

### 输出最低要求

1. **必须写明数据时点**：如"数据截至 2026-06-18 收盘"
2. **必须提示快照可能过期**
3. **估值数据必须做常识校验**
4. **不输出买卖建议**，只给事实和排序

## 顺序钻取模式

当用户从行业全景切入，逐步深入个股时：

```
第1层：行业全景扫描
  → 输出：行业大叙事、关键数据、主要标的概览表、与用户持仓交叉分析
  → 等待用户选择具体标的

第2层：个股 QARP 分析
  → 输出：估值快照、三道闸门、估值纪律、买入前必答、组合检查

第3层：多标的横向对比
  → 输出：三强/多强对比表（PE/ROE/FCF质量/增速/股息/资产负债表逐项对比）
  → 排名建议（性价比排序）+ 理想买入区间表

第4层：竞争格局分析（Porter五力）
  → 输出：五力评分、交叉验证、时间维度趋势
  → 整合到最终投资备忘录
```

**关键原则**：每层输出结论先行，详细数据作为支撑。用户简短提问（如"HUBB呢"）保持当前框架换标的。明确要求新方向才进入下一层。

## 分析师一致预期降级方案

当本地无研报 PDF 时，优先用 StockAnalysis.com 获取分析师一致预期数据：

```
https://stockanalysis.com/stocks/{ticker}/forecast/
```

该站点提供（无反爬，数据来自 S&P Global Market Intelligence）：
- 一致评级分布（Strong Buy / Buy / Hold / Sell）
- 平均/中位数/最高/最低目标价
- 营收和 EPS 预测（当前财年+未来财年）
- 覆盖分析师数量

## 异常处理

| 异常 | 处理 |
|------|------|
| WebSearch 返回无关结果 | 换关键词重试 1 次 |
| 标的行情数据为空 | 检查代码/代理，跳过该标的 |
| 持仓文件不存在 | 标注"无持仓数据"，继续 |
| Yahoo 限流 | 间隔 ≥3 秒重试，或用浏览器降级 |
| 连续 5 条搜索失败 | 熔断，用已有数据出报告 |
